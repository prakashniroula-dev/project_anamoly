\section{Introduction}
The \textbf{TCP-Based Web Server in C++} project is an academic implementation of a lightweight web server that communicates with clients over the TCP protocol and serves static web resources such as HTML files. We selected this project to strengthen our understanding of how real-world client--server communication works beyond high-level frameworks, and to gain hands-on experience with core networking concepts \cite{stevens-unp}. The project addresses the need to understand the internal workflow of web systems, including socket creation, binding, listening, accepting connections, processing HTTP requests, and returning valid responses \cite{beej}.

The implementation is developed in \textbf{C++}, using standard libraries such as \texttt{iostream}, \texttt{fstream}, \texttt{string}, and \texttt{filesystem}, along with socket-related system libraries (e.g., Winsock on Windows) \cite{msdn-winsock}. Object-Oriented Programming principles are central to the design, where socket and server responsibilities are separated into reusable classes. This modular structure improves readability, maintainability, and extensibility, making the system easier to test and enhance in future versions.

\section{Objectives}
\begin{itemize}
    \item To develop a lightweight TCP-based web server in C++ that demonstrates practical use of Object-Oriented Programming concepts.
    \item To process HTTP GET requests and deliver static web content accurately and reliably using socket communication.
\end{itemize}

\section{System Design}
The system follows a straightforward client--server execution flow. The program begins by initializing the networking environment and launching the server on a user-defined port. Once active, the server enters a continuous accept loop where it waits for client connections, receives incoming HTTP requests, parses the requested resource path, and generates an appropriate response.

If the requested file is available in the configured root directory, the server returns an HTTP 200 response with the file content \cite{rfc9110}. If the path refers to a directory, the server provides a directory listing response. For unavailable resources, it returns an HTTP 404 response. After sending the response, the connection is closed, and the server returns to the accept state to handle the next client request. This cycle reflects the classic \textit{accept--read--respond--close} model used in basic TCP web server implementations \cite{stevens-unp}.

\section{Features}
\begin{itemize}
    \item Serves static web resources such as HTML files through a TCP connection.
    \item Uses socket-based client--server communication for handling browser requests.
    \item Follows a modular class-based design for socket management and server operations.
    \item Generates essential HTTP responses, including \texttt{200 OK} and \texttt{404 Not Found} \cite{rfc9110}.
\end{itemize}

\section{Implementation}
\begin{itemize}
    \item \textbf{Programming Language:} C++
    \item \textbf{Core Libraries:} \texttt{iostream}, \texttt{fstream}, \texttt{string}, \texttt{filesystem}, and socket-related headers \cite{msdn-winsock}
    \item \textbf{Implementation Approach:} Object-oriented class design for socket setup, server execution, and request handling
    \item \textbf{Functional Scope:} Accepts HTTP GET requests and serves static resources from the configured root directory
    \item \textbf{Reliability Measures:} Basic validation for socket initialization, binding/listening, connection acceptance, and file/path access
\end{itemize}

\section{Limitations}
\begin{itemize}
    \item The server currently focuses on the HTTP \texttt{GET} method, with limited support for other request methods.
    \item Request parsing is intentionally simple and suitable for academic demonstration, not full production use.
    \item Concurrent client handling is basic and may be limited under higher request load.
    \item Advanced security features such as HTTPS/TLS and comprehensive hardening are not included in the current version \cite{nginx}.
\end{itemize}

\section{Future Enhancements}
\begin{itemize}
    \item Introduce multithreading or asynchronous I/O to improve concurrent client handling.
    \item Extend HTTP support with better protocol compliance and accurate MIME type handling.
    \item Add structured logging, configurable server settings, and clearer runtime error reporting.
    \item Integrate HTTPS/TLS and stronger request validation to improve communication security \cite{nginx}.
\end{itemize}

\section{Conclusion}
This project presents a simple and functional TCP-based web server developed in C++. It helped us gain practical understanding of socket programming, HTTP request handling, and object-oriented design. The current implementation provides a strong academic foundation and can be improved further with better concurrency, security, and protocol support.
